# Codex 첫 개발 지시서 — ROUTINC

아래 프롬프트를 Codex에서 저장소 `limjh719-ops/routinc`를 선택하고 실행하세요.

---

당신은 ROUTINC의 시니어 풀스택 엔지니어이자 UX 개발자입니다.

1. 저장소의 `README.md`와 `docs/PRODUCT_SPEC.md`를 먼저 읽으세요. 기존의 제품 정의와 우선순위를 임의로 변경하지 마세요.
2. 이번 작업의 범위는 **Sprint 0: 프로젝트 기본 구조 + 로그아웃 랜딩 + 로그인/회원가입 UI + 역할별 대시보드 목업** 입니다. 백엔드 및 완전한 메시징을 한 번에 구축하지 마세요.
3. TypeScript + Next.js App Router + Tailwind CSS를 사용해 모바일 우선 반응형 프로젝트를 만드세요. 신뢰할 수 있는 최신 안정 버전을 사용하고 버전 선택은 결과에 명시하세요.
4. 메인 주소 접속 시 **로그아웃된 랜딩 화면**이 우선 보이도록 구현하세요. 설명은 한국어로, 브랜드는 ROUTINC / 루틴크, 핵심 카피는 '운동의 기록을 넘어, 소통까지.'입니다.
5. 로그인/회원가입 화면에는 '트레이너로 시작하기' / '회원으로 시작하기'를 분리하세요. 인증 연결 전에는 목업임을 분명히 표시하고 실제 로그인 성공으로 오해하게 하지 마세요.
6. 로그인 후의 화면을 미리 보기할 수 있도록 트레이너 대시보드/회원 대시보드/운동 기록 상세와 댓글 UI의 **샘플 데이터 기반 목업**을 만드세요. 샘플 데이터는 가상이며 실제 회원 정보를 사용하지 마세요.
7. 트레이너는 미답변 질문함, 회원목록이 보이고 회원은 내 운동/식단 기록과 받은 피드백이 보이는 화면을 만드세요.
8. **핵심 경험**: 기록별로 회원이 질문 → 트레이너가 코멘트 → 회원이 다시 질문하는 2방향 댓글 UI를 목업으로 구현하세요. 카카오톡이나 전화번호는 요구하지 않습니다.
9. Supabase 실제 연결과 DB/RLS는 별도 다음 스프린트로 남겨도 되지만, 확장 가능한 폴더/컴포넌트 구조를 마련하세요. 보안 없는 가짜 인증을 실제 인증처럼 구현하지 마세요.
10. `.env.example`을 만들 경우 키 이름만 넣으세요. 실제 API Key, 비밀번호, 개인정보를 절대 커밋하지 마세요.
11. 구현 후 가능한 범위에서 `npm install`, 빌드, 린트/타입검사를 실행하고 결과를 보고하세요. 실행 불가 시 이유를 정확하게 적으세요.
12. 마지막 보고에 파일 구조, 실행 방법, 디자인 결정, 구현한 범위, 미완성된 기능, Sprint 1 권장 작업을 간결히 정리하세요.

완료 조건: 휴대폰 화면으로 볼 수 있는 ROUTINC 랜딩 + 트레이너/회원별 데모 화면 + 양방향 기록 댓글 목업이 동작하고, 소스가 저장소에 저장돼 있어야 합니다.
