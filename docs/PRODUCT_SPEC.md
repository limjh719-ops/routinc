# ROUTINC 1.0 — 제품 요구사항 및 화면 설계 (PRD)

버전: 0.1 / 2026-10-17
상태: MVP 구현 기준안 (사용자 테스트 후 변경 가능)

## 1. 제품 정의
**ROUTINC는 PT 트레이너와 회원이 운동·식단·컨디션에 대해 양방향으로 소통하고, 그 피드백을 기록에 연결해 축적하는 플랫폼이다.**

잘못된 출발: AI가 정해진 운동 루틴만 자동 생성해서 일방적으로 제공.
올바른 출발: 회원 ↔ 트레이너의 실제 대화를 정리하고, 상담·수업·기록 업무를 효율화.

- 결제 고객: 1인 트레이너 및 소규모 PT 스튜디오 (가설; 검증 필요).
- 실제 사용자: 트레이너와 회원.
- 경쟁 우위 가설: 기록별 대화 + 일반 1:1 메시지 + 미답변 질문함 + 커스텀 상담일지.
- 서비스 목표: 빠르게 질문을 남기고, 쉽게 답변하고, 지난 피드백을 10초 안에 재확인하는 경험.

## 2. 두 역할
### 트레이너 (trainer)
- 담당 회원 관리, 회원 초대, 회원별 기록 열람
- 운동·식단·컨디션 기록 생성 및 수정
- 기록별 댓글, 일반 1:1 메시지
- 미답변 질문·알림 확인
- 상담 양식 커스텀: **기본정보 항목은 유지하고 '운동 목적' 이후 항목 추가/편집**
- 답변 가능 시간·알림 관리

### 회원 (member)
- 계정 생성 및 초대 링크/코드로 담당 트레이너와 연결
- 본인 운동·식단·컨디션 기록 작성
- 운동 영상/식사 사진 첨부(단계적 도입)
- 기록별 질문·답변과 일반 1:1 대화
- 본인 기록·피드백 검색 및 수정 (정책 범위 내)

**금지**: 전화번호/카카오톡 친구 추가를 필수 가입 요건으로 만들지 않는다.

## 3. 화면 명세
### A. 로그아웃 첫 화면 / 로그인
- 최초 접속 기본 상태는 공개 랜딩과 로그인·회원가입 진입 화면
- '트레이너로 시작' 및 '회원으로 시작' 구분
- 이메일 기반 로그인; 필요 시 OAuth 후속 도입
- 이메일 링크 인증 등 안전한 인증 방식 사용, 공용 테스트 비밀번호를 배포하지 않는다

### B. 트레이너 홈 (/trainer)
- 오늘 수업/주요 활동 요약(일정 기능은 후순위)
- 미답변 질문 개수, 최신 질문 5개
- 회원 목록, 회원 초대 CTA
- 필터: 전체/미답변/최근 활동 없음

### C. 회원 상세 (/trainer/members/[id])
- 기본 정보, 운동 목적, 상담 내용, 기록 타임라인
- 운동/식단/컨디션 탭
- 해당 회원과 1:1 메시지로 이동
- 상담 양식은 기본정보 고정, 목적 이후 항목 구성 수정

### D. 회원 홈 (/member)
- 오늘 운동, 최근 식단/컨디션 기록
- 받은 피드백, 새 메시지, 질문 작성 버튼
- 담당 트레이너 프로필 및 답변 가능 시간

### E. 기록 상세 (/records/[id])
- 기록 종류(workout/meal/checkin), 제목, 시간, 본문, 운동 중량/반복 수 등 선택 데이터
- 이미지/영상 첨부 시 권한 확인
- **동일 기록에 회원·담당 트레이너가 댓글을 연속으로 작성**
- 작성자/작성 시각, 댓글 편집·삭제(본인만), 미확인 표시
- '이 기록을 채팅에 공유' 기능은 후속 단계

### F. 1:1 메시지 (/messages/[conversationId])
- 기록과 관계없는 일반 질문을 위한 양방향 대화
- 회원과 연결된 트레이너만 해당 대화에 접근
- 읽음 상태·알림; 파일 전송은 후속 단계

### G. 트레이너 질문함 (/trainer/inbox)
- 기록 댓글과 일반 대화 중 답변이 필요한 항목을 통합 표시
- 미답변/완료 필터, 최신순 정렬
- 클릭하면 원본 기록 또는 메시지로 이동
- 빠른 답변 템플릿은 2차 개발

### H. 설정 (/settings)
- 계정/역할/프로필 수정
- 답변 가능 시간, 알림 설정
- 로그아웃, 계정 및 데이터 삭제 요청 경로

## 4. MVP 필수 기능과 우선순위
### P0 — 첫 사용 가능한 데모
1. Next.js 프로젝트, 모바일 우선 UI, 로그인/로그아웃, 권한별 라우팅
2. 트레이너 ↔ 회원 초대 링크/코드(만료·일회성·관계 승인)
3. 트레이너 회원 목록 및 회원 상세
4. 운동/식단/컨디션 기록 CRUD
5. 기록별 양방향 댓글, 본인 댓글 수정/삭제
6. 트레이너용 미답변 질문함 + 앱 내부 알림
7. 일반 1:1 메시지
8. 회원 상담 기본정보 + 운동 목적 이후 사용자 지정 질문

### P1 — 베타 이후 개선
- 사진 업로드, 운동 영상 업로드(파일크기 제한·저장비용 관리)
- 사진 및 영상에 대한 맥락 있는 피드백
- 기록 검색, 트레이너 답변 템플릿
- 실제 사용량·답변 속도 대시보드
- AI 답변 **초안만** 생성; 트레이너 승인 전 발송 금지

### P2 — 수익화 및 확장
- 구독결제·요금제, 재등록 일정
- 스튜디오 다중 트레이너 권한
- 푸시 알림, 외부 캘린더, 회원용 리포트, 앱스토어용 네이티브 래퍼

**중요**: 앱 내부 알림은 먼저 구현, 푸시/SMS/카카오 알림은 통합하지 않음.

## 5. 데이터 모델 초안
- profiles: user_id, role, nickname, created_at
- trainer_member_links: id, trainer_id, member_id, status, created_at, revoked_at
- invites: id, trainer_id, token_hash, expires_at, used_at, created_at
- records: id, member_id, trainer_id, author_id, kind(workout/meal/checkin), title, body, structured_data(jsonb), created_at, updated_at
- comments: id, record_id, author_id, body, created_at, updated_at, deleted_at
- conversations: id, trainer_id, member_id, created_at
- messages: id, conversation_id, sender_id, body, created_at, read_at
- notifications: id, recipient_id, source_type, source_id, read_at, created_at
- consultation_templates: id, trainer_id, fields(jsonb), created_at, updated_at
- consultation_entries: id, member_id, trainer_id, template_id, answers(jsonb), created_at
- attachments(P1): id, record_id, owner_id, storage_path, mime_type, size_bytes, created_at

초기 구현에서 불필요한 테이블은 줄여도 되지만 **회원-트레이너 연결 관계 및 레코드 접근권한 검증은 필수**.

## 6. 권한·보안·개인정보
- Supabase RLS를 켜고 모든 회원 개인 데이터 테이블에 정책 적용.
- 회원은 자신의 기록과 연결된 트레이너와의 대화만 접근.
- 트레이너는 활성 연결 상태의 담당 회원 기록만 접근.
- 관계 종료 시 접근 차단 정책 정의; 사용자 데이터 삭제 및 보관 정책 별도 수립.
- 초대 토큰 원문을 DB에 저장하지 않고 해시로 관리; 만료와 재사용 방지.
- 저장소는 공개될 수 있음: 환경변수/실제 회원 기록/신체 사진/보안 키 커밋 금지.
- 식단·통증·건강 정보는 민감할 수 있으므로 수집 최소화, 개인정보 처리 안내, 접근통제, 안전한 보관이 선행되어야 함.
- 이미지/영상은 private storage + 접근 권한 검증 + 임시 URL을 사용.
- 인증·권한 검사는 프론트 UI만으로 처리하지 말고 서버/RLS에서 강제.
- 실사용 회원을 베타에 넣기 전에 개인정보 및 동의 프로세스를 점검.
- AI의 운동/영양/통증 관련 조언을 회원에게 무검토 자동 전송 금지.

## 7. UX 원칙
- 한 화면에서 현재 '회원/트레이너' 역할이 명확함.
- 기록 열기 → 질문 작성까지 2~3탭.
- 질문함에서 미답변이 먼저 보이고 해당 기록으로 바로 연결됨.
- 기본 화면은 **로그아웃 상태 랜딩**.
- 모든 주요 화면은 모바일 세로폭 375px에서도 무리 없이 사용 가능.
- 전문용어를 남발하지 않고 쉬운 한국어 사용.
- 기록에 남긴 피드백은 대화 맥락(운동명·식사 날짜 등)이 함께 보임.

## 8. 인수 조건 (Definition of Done)
- 트레이너 A와 회원 B가 전화번호 없이 초대 링크로 연결할 수 있다.
- B가 운동 기록을 생성하고 질문을 남길 수 있다.
- A가 질문함에서 질문을 확인하고 기록에 댓글로 답할 수 있다.
- B가 답변을 확인하고 **다시 댓글을 남길 수 있다**.
- B가 식단 기록을 올리고 동일한 양방향 소통을 진행할 수 있다.
- A/B가 일반 1:1 메시지를 주고받을 수 있다.
- 제3자 C가 A/B의 비공개 기록·채팅·파일을 읽거나 수정할 수 없다 (권한 테스트).
- 기록 새로고침 후 데이터가 유지되며, 로그아웃 후 비공개 페이지로 진입할 수 없다.
- 트레이너가 상담 양식을 만들 때 기본정보를 보존하고 운동 목적 이후 질문을 커스텀할 수 있다.
- 빌드/타입검사/린트가 통과하며 테스트 방법이 README에 문서화된다.

## 9. 초기 성과 지표 (목표값, 검증 필요)
- 회원 초대/연결 1분 이내
- 트레이너가 피드백 작성 1분 이내
- 지난 피드백 찾기 10초 이내
- 트레이너 5명+회원 10명의 파일럿 사용 후 정성 인터뷰
- 반복 사용률, 미답변율, 주당 관리 소요시간 기록

## 10. 개발 운영 규칙
- 첫 과제는 프로젝트 부트스트랩 및 디자인 구조; 전체 기능을 한 번에 생성하지 않는다.
- 각 단계 완료마다 변경 파일, 실행방법, 테스트 결과, 미완성 사항 보고.
- 사용자 확인 없이 비용 발생 서비스 가입, 유료 API 사용, 배포, 실제 고객 초대 금지.
- 기술 스택: Next.js App Router, TypeScript, Tailwind CSS, Supabase(Auth/Postgres/Realtime/Storage; 필요한 것부터).
